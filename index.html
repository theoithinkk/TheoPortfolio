Oct 2026 · Secrets · Git · Cloud

Deleting a secret doesn't un-leak it

Why my secret scanner reads Git history, not just the current files.

Read note

When we built the Galicious Secret Scanner, the most important test wasn't in the latest commit. In our VulnRepo fixture, a "security cleanup" commit moved hardcoded credentials into environment variables. The working tree looked almost clean, but the AWS secret key, a GitHub token and a database password were all still one git log -p away.

The lesson for GRC: the control isn't "remove the secret", it's rotate it, then remove it. Removing it without rotating leaves the likelihood exactly where it was, with a false sense of closure.

In a risk register, a leaked credential that was only deleted should stay open until there's evidence it was rotated.

Oct 2026 · Control mapping

One finding, five frameworks

Mapping an exposed .git directory, and why the rationale matters more than the IDs.

Read note

In DarkHole V2, an exposed .git directory was the first step to root. Here's how that one finding maps:

  • OWASP Top 10 (2021): A05 Security Misconfiguration.
  • CIS Controls v8: Control 4, Secure Configuration of Enterprise Assets and Software.
  • NIST SP 800-53 Rev. 5: CM-6 Configuration Settings, CM-7 Least Functionality.
  • ISO/IEC 27001:2022 Annex A: 8.9 Configuration management, 8.4 Access to source code.
  • PCI DSS v4.0: Requirement 2, apply secure configurations to all system components.

Matching IDs is the easy part. What makes a mapping useful to an auditor is the why: the server shipped files it never needed to serve (least functionality), and source code with credentials was reachable by anyone (access to source code). That rationale is what AuditBridge stores next to every mapping.

Oct 2026 · Risk

5×5 risk scoring without fooling yourself

The matrix is for sorting risks, not measuring them.

Read note
  • The score is ordinal. Likelihood × impact gives 1–25, but a 12 isn't "twice as risky" as a 6. Use it to rank and prioritize, not to do math.
  • Define the levels before you score. Write down what each likelihood and impact level means for this organization, or two people will score the same risk differently.
  • Score inherent and residual separately. The gap between them is the value of the control, so record the evidence that the control actually works.
  • Explain every score. AuditBridge keeps a one-line rationale next to each rating, so the register still makes sense months later.

Oct 2026 · Banking · In progress

Reading BSP Circular 1140 as a student

Notes from preparing for IT risk roles at Philippine banks.

Read note

BSP Circular No. 1140 (2019) sets the Bangko Sentral's expectations for how supervised financial institutions manage IT risk. I'm reading it area by area:

  • IT governance, with oversight from the board and senior management
  • The IT risk management process: identify, measure, control, monitor
  • Information security
  • IT operations, projects and outsourcing to third parties

What stands out so far: expectations scale with how complex an institution's IT is, and accountability sits with the board, not only the IT team. These notes are a work in progress, so read the circular itself for anything you rely on.
