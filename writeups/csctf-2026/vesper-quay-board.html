The trick

Two JSON parsers, one request. Go's encoding/json folds key case and takes the last duplicate; Python's json is exact and case-sensitive. The desk validated the UPPER-case keys while the quay executed the lower-case ones — a confused-deputy that turns a "safe" validation into attacker-chosen code on the box that holds the signing key. From there the signature is genuine, so the forged-warrant defense (requiring a station signature) is satisfied by the station itself. Defensive takeaways (API security / GRC angle): - One canonical parse. Never let a gateway/validator and the executor parse the same bytes with different libraries - Case-insensitive key matching (Go encoding/json default) is a footgun next to a case-sensitive consumer. Decode - Don't run an interpreter on request-controlled argv, even "only for the legacy courier". The courier check was the - Keep signing oracles off any box reachable by untrusted input. 01Start point: GET /v1/openapi.json on the desk.

  • What I found: /v1/warrants/current (approved_courier, legacy_courier, quay_id, warrant_id), POST /v1/warrants (desk reads courier/argv, forwards the RAW body to the quay), POST /v1/corrections (returns clearance_code once a station signature verifies), POST /v1/reset (clears submissions + the 40-POST/10-min quota). Current case: approved c-38dec5, legacy c-cc024e, quay QY-3733, warrant WR-224A.

02Pivot: the desk/quay parser differential.

  • Desk rule: courier must be approved, argv must be [] or ["status"]. Quay rule: it runs python only when desk courier == approved AND quay courier == legacy. Since approved != legacy, the two parsers must disagree.
  • Both are JSON "last-wins", so duplicate keys and \u-escapes don't split them (both decode identically). Concatenated objects are rejected (strict). The real split is CASE: the desk is Go (encoding/json matches keys case-INSENSITIVELY), the quay is Python json (keys EXACT, case-sensitive). So: {"courier":"c-cc024e","argv":["-c","<code>"],"COURIER":"c-38dec5","ARGV":["status"]} Desk (Go) folds COURIER/ARGV onto courier/argv, last-wins -> approved + ["status"] -> ACCEPT. Quay (Python) reads the exact lowercase keys -> legacy + ["-c","<code>"] -> runs `python3 -I -c <code>`.
  • Confirmed: quay loader ran `print(42)` -> loader_stdout "42". Remote code execution on the quay.

03Pivot: what the quay child has (dumped os.environ via the loader).

  • STATION_SIGN=/usr/local/bin/station-sign (Ed25519 signer using the quay key), STATION_KEY=/tmp/station.key, EDGE_URL=http://127.0.0.1:8080, and SUBMISSION_ID/QUAY_ID/WARRANT_ID/COURIER_ID(=legacy). FLAG is deliberately not in this environment. So I cannot sign off-box, but I can call STATION_SIGN — which is precisely "a release the quay actually runs".

04Pivot: the correction request schema (why every guess returned BAD_REQUEST).

  • Corrections are Ed25519 over the RFC 8785 (JCS) bytes of {applied_primary, courier_id, quay_id, submission_id, warrant_id}. My bodies kept failing "Correction could not be read." Reading the server source via the RCE settled it: the quay app is /opt/station/*.py (Python) but the desk/edge is a Go binary at /usr/local/bin/edge. Its struct tags are applied_primary, courier_id, quay_id, submission_id, warrant_id, and signature — the signature member is "signature", NOT "station_signature", and the decoder rejects unknown members. world.py's signed_fields() hardcodes applied_primary=False and courier_id=legacy.
  • So the body is exactly those five fields + "signature" (standard Base64), nothing else.

05Exploit (all inside one loader, server-side, so the submission never expires):

  • canonical = {"applied_primary":false,"courier_id":"c-cc024e","quay_id":"QY-3733","submission_id":"<sub>","warrant_id":"WR-224A"} (JCS: keys sorted, bool before string, no spaces — matches world.canonical and its unit test).
  • sig = STATION_SIGN(canonical) (64 bytes) -> standard Base64 -> "signature".
  • POST EDGE_URL/v1/corrections with the five fields + signature -> 200 {"clearance_code":"CSCTF{9zAhGxCqntrgDYN2GhxrnII8}"}.
